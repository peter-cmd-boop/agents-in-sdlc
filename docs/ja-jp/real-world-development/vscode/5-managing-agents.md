GitHub Copilot をエージェントモードで使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行などを自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイル編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を受け入れるか元に戻すか選択し、追加のプロンプトでエディターを離れずに作業を調整、拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして受け入れます。
- 作業中のエージェントに指示を出し、ハイコントラストに加えてライトモードも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも切り替えられるようにします。新しい会話を最初から始めるのではなく、既存のセッションに指示を出して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが行う各手順、調査したファイル、実行したコマンド、提案した編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を元に戻し、エージェントにもう一度試させます。
4. チャット上部にある **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** の確認を表示します。許可する前に、実行するコマンドを確認してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に変更内容の概要が表示されます。

## エージェントにライトモードを追加するよう依頼する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。チャットセッションを続けると、エージェントはこれまでに変更したコンポーネント、スタイルの方法、ローカルストレージのパターンを把握したまま作業できます。

1. Copilot Chat の入力欄に次のプロンプトを送ります。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはこれまでの変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同様に、新しい編集を確認します。それぞれの差分で **Keep** または **Undo** を選択します。
4. エージェントが意図と異なる方向に進んだ場合 (例: 好ましくない方法でトグル UI をリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、説明を追加して続けます。

> [!TIP]
> 進行中のセッションに指示を出すと、最初からやり直すよりも早く調整できます。たとえば、CSS を簡潔にする (セレクターを重複させず CSS 変数を使う)、方向を修正する (3つ目のトグルを追加せず、既存の設定パネルにライトモードを加える)、範囲を広げる (両方の切り替えにキーボードショートカットを追加する) などの追加プロンプトを送ります。

## 作業中の変更をレビューする

変更をコミットする前に、エージェントが変更したファイル全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイル全体を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。アクセシビリティ用カスタムエージェントの指針が反映されていることを確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定の永続化などが対象です。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンでブランチを公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、指示を出しました。ファイル編集を確認して受け入れるか元に戻すかを選び、コンテキストを失わずに追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個別のファイル編集を受け入れたり元に戻したりしました。
- 追加プロンプトで作業中のセッションを方向付けました。
